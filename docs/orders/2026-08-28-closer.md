## 3. WHAT THIS ORDER EXECUTES, IN VIC'S SEQUENCE

**(a) Ruling 1 — extend the gate.** The class currently binds `build_fcf_series` only. Extend
to the **classifier** (no stage computed or written) and the **evaluator** (no pillars, no
E(R), no evaluation row carrying numbers). Retire the **8 stored `lifecycle_stage` rows** for
BK/C/JPM/USB with a typed reason — additive column, rows never deleted, and `tolerance_for()`
must stop reading them.

★ **`tolerance_for()` FALLS TO THE DEFAULT BAND, NOT TO "NO BAND".** "No band" has no
representation in a guard that needs a threshold. The standing fail-closed rule already says
an unclassified name gets the DEFAULT and never the widest, so a retired stage lands on 15%
with a reason naming the class. These names are not scored at all, so the band is unreachable
in practice; it is defined rather than left undefined.

**(b) Ruling 2 — recompute-on-detect, halt-and-report.** A typed exception at the stage-write
boundary. **The approval channel is a NEW surface, not `lifecycle_overrides`** — that table
means "the approved stage REPLACES the computed one", which is a different question from "may
this computed stage be persisted". Overloading it would be exactly the semantic conflation
this project punishes. Then run the sweep once, read-only, and report every catch.

**(c) Ruling 4 — the currency guard.** Score-bearing fields, partitioned by whether a currency
error can reach them:

- **MONETARY (guarded):** `total_debt`, `total_cash`, `free_cashflow`, `operating_cashflow`,
  `market_cap`, `enterprise_value`, `current_price`, `target_mean_price`.
- **CURRENCY-NEUTRAL (not guarded, and the reason is stated):** margins, `roe`, `roa`,
  `current_ratio`, `debt_to_equity`, `revenue_growth`, `trailing_pe`, `forward_pe`,
  `price_to_book`, `ev_to_ebitda`, `ev_to_revenue`, `fcf_yield`, `beta` — every one is a
  ratio whose numerator and denominator share a basis, so a KRW/KRW reading is CORRECT.
  Verified on SKHY: `freeCashFlowYieldTTM = 0.0777`, and KRW TTM FCF ÷ KRW cap reproduces
  7.77% to the decimal. Blocking these would discard valid data.
- **NOT CURRENCY (not guarded):** `shares_outstanding`, `analyst_count`.

**★★ RULINGS 3 AND 4 ARE COUPLED, AND APPLYING 3 WITHOUT 4 WOULD MANUFACTURE THE EXACT DEFECT
4 EXISTS TO KILL.** `core/pillars.py:237-238` computes `fcf / yf.market_cap.value * 100`.
Today both legs are KRW for SKHY, so the ratio is accidentally CORRECT. Ruling 3 makes
`market_cap` USD. **If `free_cashflow` were left on its KRW basis, that division becomes wrong
by a factor of ~1,378 — a brand-new cross-currency trap, created by the fix.** The guard
blocking `free_cashflow` is what makes ruling 3 safe. **They land together or not at all.**

**(d) Ruling 3 — the SKHY anchor.** Source `market_cap` from `market-capitalization` (USD),
live at write time, and persist the anchor as a row with its endpoint, value and timestamp.
`overrides` is NOT the destination: measured, it is read **only** by `web/app.py` and never by
the pipeline, so a row there would be an anchor nothing reads.

**(e)** Pre-flight rescope — doc-level. **(f)** Punch-list census — read-only.
