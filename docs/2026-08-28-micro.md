## 2. GOOG −0.79% — READ-ONLY DIAGNOSIS. TYPED ANSWER: A BASIS DIFFERENCE, NOT A DEFECT

### What the figure actually measured

The ratio of **`market-capitalization?symbol=GOOG`** (ruling 3's new endpoint) to
**`key-metrics-ttm?symbol=GOOG`** (the old one) — same symbol, same day. Re-measured live
today and it reproduces exactly:

| | GOOG | GOOGL |
|---|---|---|
| `key-metrics-ttm.marketCap` | 4,194,470,750,615.0005 | 4,194,470,750,615.0005 |
| `market-capitalization.marketCap` | **4,161,158,232,742** | 4,194,470,750,615.0005 |
| `profile.marketCap` | 4,161,158,232,742 | 4,194,470,750,615.0005 |
| ratio new/old | **0.992058 (−0.794%)** | 1.0000 |

`key-metrics-ttm` hands GOOG **GOOGL's record byte-for-byte, down to the `.0005` float
artifact** — the fingerprint of literally the same stored value, not a coincidentally close
one. So that endpoint resolves a symbol to the **issuer's primary line**;
`market-capitalization` prices the **queried listing**. Same shape as SKHY, three orders of
magnitude down.

### Why it moved — and it is NOT a share-class carve-out

**Both caps divide by the SAME share base.** `shares-float` returns
**12,102,111,286 outstanding shares for GOOG and GOOGL identically** — issuer-wide, all
classes. Dividing through:

```
GOOGL cap / 12,102,111,286 = $346.590000   ← exactly GOOGL's quote (346.59 × shares
                                              reproduces the cap to the .0005 artifact)
GOOG  cap / 12,102,111,286 = $343.837380   ← GOOG's own cap-snapshot quote
ratio = 0.992058  →  the ENTIRE −0.79% is the Class C / Class A price spread
```

**So it is a class-specific PRICE applied to an issuer-wide SHARE BASE.**

### ★ ONE CORRECTION, AND IT IS THE REASON THIS WAS WORTH ASKING ABOUT

The closer report and the adapter comment both called the new value the **"class-C
listing"** cap. That label is wrong in a direction that invites damage: a genuinely
class-C cap would be **roughly HALF** (~5.8B of Alphabet's ~12.1B shares), not 99.21%.
A later session reading "class-C cap" beside a number that is 99% of the issuer cap has
two ways to resolve the contradiction, and one of them is halving GOOG.

**Fixed as a comment-only correction** in `adapters/fmp_adapter.py` (the one-line-correction
latitude in the order): the endpoint "prices the QUERIED LISTING", with the share-base
arithmetic and an explicit *do not halve this* note. Zero behaviour change, suite unchanged.

### Type of the finding: BASIS DIFFERENCE — neither endpoint is wrong

Both are internally coherent and answer different questions: "what is Alphabet worth" vs
"what is the line quoted as GOOG worth". This is the **same class as the ruled LLY
EDGAR/FMP capex coexistence** — permitted to disagree, must not be "fixed". For a row
**labelled GOOG**, the new value is the more correct of the two. **No fix beyond the
comment. No code change. Nothing further recommended.**

### Why nothing moved — threshold absorption, NOT independence, and the margin is thin

`market_cap` has **exactly one score-bearing consumer**: `core/pillars.py:237-238`,
`fcf / market_cap`, feeding a **single binary threshold at 3% FCF yield**. GOOG's yield goes
**1.747% → 1.761%** — both far below the only rung that reads it. That is the whole
mechanism behind "ZERO PILLAR SCORES MOVED".

So the claim is true but it is a **weaker guarantee than it sounds**, and measuring the rung
distance across the universe shows why:

| name | FCF yield | cap move needed to cross the 3% rung |
|---|---|---|
| **V** | 3.028% | **+0.93%** |
| **NOW** | 3.059% | +1.97% |
| GOOG | 1.761% | +41% |

**GOOG's endpoint switch moved a cap by 0.79%. V sits 0.93% from losing its FCF-yield
bonus point.** Had V been the dual-class name, the same switch would have moved a pillar
score. **Zero movement was proximity, not structure** — worth recording before the next
change to a cap-shaped input is waved through on "the last one moved nothing".

### Sweep across all 28 — reproduces the closer's result exactly
